# Windows 版产品目标

状态：规划草案。基线与文档导航见 [README](README.md)。

## 1. 产品定位

面向需要图层合成、图片修饰和简单文字排版的 Windows 用户，提供可离线运行的桌面编辑器。延续 Compositor 的图层、蒙版、非破坏变换和快捷键工作流，并能与当前 Mac 版交换工程。

这次建设的目标是 Windows 版 Compositor，不是把所有开源图像库组合成新平台，也不以复刻 Photoshop 全部功能作为发布条件。

## 2. 目标用户与核心任务

| 用户 | 核心任务 | 完成的定义 |
| --- | --- | --- |
| 运营与视觉设计人员 | 导入素材、调整图层、抠图、加字、输出宣传图 | 全程在本地完成，PNG/JPEG 输出正确，工程可再编辑 |
| 摄影与图片修饰用户 | 选区、修复、仿制、调色和局部蒙版 | 操作可撤销，透明边缘正常，预览与导出一致 |
| Mac/Windows 混合使用者 | 在两台机器间继续编辑同一工程 | 支持基线 v1–8；层级和元数据保留，不静默栅格化文本/调整层 |

## 3. 五项产品目标

| 目标 | 衡量方式 |
| --- | --- |
| G1：能完成核心合成工作流 | 从新建到导入、分层、变换、蒙版、加字、保存、重开、导出的验收脚本全部通过 |
| G2：工程数据可靠 | 所有必需格式样本往返不丢字段；保存失败不破坏旧工程；取消操作不产生伪历史 |
| G3：常用编辑保持响应 | 在固定 Windows 参考机和图片集上满足 [性能目标](validation-release.md)，不以 Mac 耗时推算 Windows 结果 |
| G4：符合 Windows 操作习惯 | 中文 IME、Ctrl 快捷键、DPI、文件拖放、多个项目和系统剪贴板验证通过 |
| G5：普通用户可安装与维护 | 干净系统安装可运行；依赖齐备；更新失败能重新启动；卸载不删除用户工程和导入字体 |

## 4. 版本划分

| 版本 | 面向谁 | 必须达到 | 可以暂缺 |
| --- | --- | --- | --- |
| 技术原型 M1 | 开发者 | 候选通过相同的合成、笔划/撤销/导出、变换文本输入、最小格式往返实验；形成选型记录 | 完整 UI、兼容读写、发行安装器 |
| Alpha，M3 后 | 内部验证者 | 新建/导入、图层、选区、基本笔刷、蒙版、变换、可靠保存和 PNG/JPEG 导出；只编辑已支持的工程 | 高级滤镜、完整文本编辑、AI 抠图、HEIC 等按 PRD 分期 |
| Beta，M6 后 | 小范围真实用户 | 完成基线功能，含 v8 文本/字体、调色、修复、抠图、四种导入格式和工程互读；提供候选安装包 | 自动更新正式渠道、公版签名发布及低优先级优化 |
| 1.0，M7 后 | 一般 Windows 用户 | Beta 功能通过发布门槛、干净系统安装、数据安全、更新和用户说明验证 | 明确列在不做范围中的能力 |

Alpha 不等于“任意 v8 工程均可编辑”。不支持的已知图层语义必须阻止编辑保存，必要时只提供清晰标记的受限查看；不能显示近似结果后允许覆盖原工程。Beta 才承诺基线全部需求。

## 5. 首版范围与限制

建议首发 Windows 11 x64，键鼠为必需输入，数位笔基础点击/移动纳入测试。当前基线之外的笔压动态、倾斜笔刷、触摸手势先不扩展。Windows 10 和 ARM64 按设备、依赖和需求另决，不宣传为已支持。

图像处理以当前 sRGB 工作空间和现有像素精度为基线；30,000 像素单边、100 MP 等现有格式限制是输入校验上限，不是任意图层组合都能流畅编辑的性能保证。实际验收使用固定图片集。

第一版建议继续使用 `.comp` 文件夹工程。用户通过“打开工程文件夹”、拖放或最近项目进入；跨设备复制整个文件夹。暂不增加 Windows Shell 扩展来模拟 Mac 文档包，也不承诺双击该文件夹就直接启动应用。

文字工程打开时保留已保存栅格，不因平台字体渲染差异自动重排；明确编辑后按 Windows 布局生成新结果。文字层缩放触发重绘的策略须由 D-11 决定，因为当前 Mac 会重绘，而最初计划希望保留栅格；不能混称为相同行为。缺失字体需提示；替换由用户明确选择。像素编辑和图像尺寸变更造成的栅格化应明确反馈并可撤销。

本地编辑不要求账号或联网。更新检查和首次获取可选 AI 模型可以需要网络，必须区分下载模型和上传图片；本计划不引入远程图像处理服务。模型下载后支持离线推理。

## 6. 不属于本轮目标

- PSD/PSB 完整导入导出、RAW、CMYK、HDR、16/32 位全流程。
- 云同步、多人协作、登录付费系统、插件市场、移动端或浏览器版。
- 多样式富文本、文字沿路径、艺术字变形、任意字体自动随工程分发。
- 同时重写 Mac UI 或强制 Mac/Windows 共用一个 UI 框架。
- 为迁移自动换成另一个完整编辑器的 fork；若选这条路，需要重新评估产品身份、工程格式和维护成本。

## 7. 范围与交付管理

团队人数、C++/C# 熟悉程度、Windows 实机和签名资源目前未知，因此先给任务依赖和退出条件，不给无依据的发布日期。M0 先恢复可运行的 Mac 回归基线，M1 通过后再按数据/文件、渲染、交互、文本、发行五类实际成本估算人日与安排日期；不按任务数量平均分配工时。

若模型、HEIC 或高级滤镜未通过 Beta 验收，版本保持 Alpha/预览状态，或由产品范围变更明确缩减承诺；不能仅调整版本名就宣称等价完成。缺少公版签名资源不妨碍内部原型，但会阻止达成本计划的 1.0 发布条件。
