# Windows 产品需求 PRD

状态：规划草案。产品目标见 [产品目标](product-goals.md)，执行映射见 [开发计划](development-plan.md)。

用户于 2026-09-21 确认：首版支持 Windows 11 x64，沿用 v8 `.comp` 文件夹工程；不扩展为单文件容器。

## 1. 基线与分期

需求基于 Mac 提交 `d562565e5f1c53a7ece4dd2d1f6c0ef3547a3c28`。工程格式 v8 已包含文本元数据，不能按旧版 v7 计划遗漏文本。[代码审计](code-coupling-audit.md)发现的测试编译阻断已在隔离实施分支修复，回归证据见[实施记录](execution-log.md)。本 PRD 仍是 Windows 待验证目标，不能以 Mac 测试通过替代 Windows 需求验收。

“Alpha/Beta”表示最晚具备完整能力的阶段，不代表 Beta 项目可从 1.0 中默认删除。所有 `P-01` 至 `P-19` 均为本计划 1.0 范围；Beta 中提前试验安装，但正式更新发行在 M7 验收。

## 2. 主界面与完整用户流程

主窗口包含菜单与项目标签、左侧工具栏、中央画布、工具属性区、图层面板和状态信息。延续当前信息组织，适配 Windows 的窗口、焦点和输入习惯；此处不要求像素级复刻 macOS 控件。

标准流程：新建画布 → 拖入素材 → 命名/组织图层 → 变换/选区 → 蒙版或修饰 → 调整颜色 → 加入文字 → 保存工程文件夹 → 关闭重开 → 导出 PNG/JPEG。

跨平台流程：Mac 保存 v8 工程 → 复制整个 `.comp` 文件夹 → Windows 打开 → 保留文本缓存和图层结构 → 修改一个受支持对象 → 保存 → Mac 重开并核对结果。

## 4. 必须写清的交互规则

### 4.1 保存、打开和未完成编辑

“保存工程”与“导出图像”是两个独立动作。未命名项目首次保存选择目标工程文件夹；覆盖既有工程只替换该工程数据，不删除同级用户目录。

打开先验证完整工程，验证成功才替换当前文档。存在超出当前 Alpha 能力的调整层或文本等语义时，禁止编辑保存；任何受限预览都必须声明不具备完整渲染保证，不提供从错误预览生成的正式导出。

首版保存期间阻止重叠编辑，沿用当前 Mac 策略；不要求新增后台保存时继续编辑的功能。若以后开放该功能，保存点必须绑定快照 revision。

切换工具、项目、图层或执行保存/导出前，必须明确提交或取消活跃编辑会话。IME 的候选状态先按输入法规则确认/取消，不能直接丢掉组合文字；具体结果由测试覆盖。

### 4.2 文本与字体

打开跨平台工程时不自动重新栅格化文字。缺失字体时显示保存的 PNG，提示原字体名称；用户可安装对应字体、明确选择替换，或取消编辑。仅移动/旋转/翻转不能悄悄改字体。D-11 已于 2026-09-21 确认：原字体可用时文字层缩放重绘；缺字体时保留缓存原画面并提示用户选择字体，禁止静默替换或覆盖原缓存。用户明确选择替换之前不得丢弃文字内容、原字体标识或自动栅格化。此为实施要求，不代表已通过 Windows 行为验收。

开始编辑后，新排版、光标、选区、点击命中和提交栅格必须来自同一布局结果；缩放/旋转/镜像后仍能准确定位输入。不得用一个原生文本框排版、另一个引擎猜测导出字宽。

空白新建后取消不留空层。编辑既有文字保留图层 ID、父组、位置和效果。像素操作使文字栅格化时须有清晰反馈且可撤销；当前 Image Size 改变像素尺寸会烘焙变换并清除 text 元数据，也需明确反馈和回归，不能与“未编辑往返保留元数据”混为一谈。字体文件默认不嵌入 `.comp`。

### 4.3 输入与快捷键

常用建议：Ctrl+N/O/S、Ctrl+Shift+S 另存、Ctrl+Z 撤销、Ctrl+Shift+Z 重做、Ctrl+C/X/V。新建/保存工程与导出保持不同菜单入口；工具单键按当前基线映射，M0 核对冲突。

输入框、文本编辑和 IME 激活时，删除键、空格、方向键、字母键优先属于编辑控件。Esc 先处理输入法组合，再处理当前操作；不能一键同时撤销输入和关闭工程。

## 5. 质量目标

正确性与数据安全是发布条件。固定参考场景下的拟定响应门槛为：常规画布交互及 4K 软笔刷更新 P95 ≤16.7 ms，笔刷 mouse-up 到历史提交 P95 ≤100 ms。这里只计明确定义的软件阶段，不代表已经达到 60 fps 或输入到屏幕 16.7 ms。

上述值、参考机与内存门槛在 M1 冻结；现阶段是产品目标。未达标要定位瓶颈或显式修改目标，不能把测试条件悄悄改轻。完整测试定义见 [验证与发布](validation-release.md)。

## 6. 发布不接受的行为

- 未支持的图层或文本被静默栅格化/删除后覆盖原工程。
- 保存失败提示成功，或重启后原工程无法恢复。
- 普通笔划、滤镜取消、中文输入导致历史错乱或跨项目污染。
- 同一已提交文档的预览与导出采用不同合成规则而明显不一致。
- 未核实模型权重许可就随安装器分发，或未告知用户就上传图片。

## 7. 需求追踪

实现 PR 写明覆盖的 P 编号和 W 编号，验收记录附对应 V 编号。发现基线缺陷时，记录输入、Mac 行为、Windows 预期和产品决定；不以复制已知缺陷作为兼容成功，也不在迁移中顺手扩展无关功能。
