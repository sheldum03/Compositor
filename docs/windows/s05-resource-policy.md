# S05 资源规则提案 v1（2026-09-24）

状态：**可执行提案，尚未冻结为验收标准**。它补齐 D-06 的具体决策输入；既有报告的 `resourceAccepted=false` 保持不变。S02 的 16.7 ms / 100 ms / 2 GiB 门槛不变。这里没有调整 GC、笔刷、缓存或生产代码。

## 范围与步骤

规则针对当前固定 4K 笔刷、历史、保存重开、关闭文档的 Avalonia 原型。沿用标准 S05 的每轮 100 次编辑及完整撤销/重做、三轮正确性要求。额外使用已实现的 27 轮诊断确定稳定区间，不把诊断计时当作 S02 性能，也不推导所有产品工作负载的预算。

1. 保留第一至九轮启动/预热数据 → 全部计入占用上限，不能删掉冷启动峰值。
2. 对比第十至十八轮和第十九至二十七轮的关闭后样本 → 同时比较最低值和最高值，避免只看最后一点或一次自然 GC。
3. 自然空闲 60 秒 → 检查关闭后延迟增长；不强制 GC 来取得通过数据。
4. 所有自然采样完成后执行一次已有诊断 GC → 只检查旧文档可回收和托管存活量，不将回收后的值代替自然占用。
5. 候选规则固定后，以相同 DLL、样本、运行库、环境记录运行两次独立 Windows 进程 → 每次均保留失败，逐文件核验并独立解码 54 张图；两次都满足规则后才评审冻结及资源通过。若调整规则，重新编号并重新做前瞻验证，不能覆盖本版结果。

## 候选判定

以下全部满足才是候选规则通过；退出码 0 **不是正式资源验收通过**。

| 项目 | 候选规则 | 取舍及依据 |
| --- | --- | --- |
| 自然采样专用内存 | 全部样本 ≤ 1 GiB | 为固定单文档路径分配 S02 进程目标的一半；这是工程预算提案，不是现有 PRD 门槛或连续峰值证明 |
| 关闭后稳定区间 | 后九轮的最低值、最高值分别不超过前九轮对应值 + 32 MiB | 同时约束底部和顶部漂移；32 MiB 小于一个 4000×4000 RGBA8 平面（约 61.04 MiB），整幅残留不能作为正常波动 |
| 关闭后句柄 | 后九轮最低值、最高值分别不超过前九轮对应值 + 8 | 保留少量系统噪声，但拒绝按文档明显累加；仍不能覆盖未统计的 GPU/原生对象 |
| 最后自然空闲 | 每个空闲样本不超过最后关闭样本 + 32 MiB | 允许保留已分配空间；约束关闭后继续增长 |
| 诊断 GC | 旧文档弱引用为 0，托管存活量 ≤ 64 MiB | 查找文档持有；64 MiB 为有限报告和基础对象的诊断预算，不能作为生产缓存配额或没有原生泄漏的证明 |

没有使用“专用内存减去 GC committed”来估计原生泄漏。自然 GC 的触发时点可能改变区间最低值，因此边界接近门槛时需要新进程复测，不据单轮校准调宽规则。有限长测无法排除低速泄漏；生产阶段仍须覆盖其他工具、长任务、GPU 资源与关闭行为。

## 校准与执行

使用 [资源判定器](../../experiments/windows/avalonia/review-s05-resources.py)：

```text
python experiments/windows/avalonia/review-s05-resources.py <原始 run/report.json>
```

判定器先执行已有完整性检查（Windows 原生、27 轮、帧序列、撤销重做、自然空闲、禁止提前 GC），再输出每项候选判断及原始报告摘要。图像解码、包身份、环境记录和退出码仍由现有独立复核完成；判定器不能替代这些检查。非 Windows、缺资源值、不完整或候选预算失败均不允许当作通过。

校准源是 [2026-09-23 已归档长测](evidence/lifecycle-s05/extended-20260923/README.md)，它发生在本规则之前。校准结果、边界及故障注入验证存于 `evidence/lifecycle-s05/resource-policy-v1/`。前瞻运行尚未开始；D-06 及 M1 仍开放。
