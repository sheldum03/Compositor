# M1 技术路线决定（2026-09-29）

**生产路线选择 Avalonia 11.3.22 / .NET 10.0.401 SDK、net10.0 / Skia 软件绘制 / 现有 C 算法 DLL。** 目标为 Windows 11 x64。Qt 6.11.2 原型归档为技术对照，不接入生产构建。此决定只放行 W-010 起的生产实现，不代表 M2–M7 或 Windows 1.0 已通过。

## 固定的实现决定

- **D-02：** 单一生产 GUI 为 Avalonia/C#，避免同时维护第二套 Qt 生产编辑器。实验代码只按实际验证过的片段迁入正式模块。
- **D-03：** 首个生产渲染后端使用 CPU 软件路径。与 C 接口相接为 8-bit 预乘 RGBA、显式 stride；蒙版为 Gray8。Windows CPU dabs 以同算法冻结图精确比较；Mac Metal 连续密度是另一算法参考，不设一个掩盖覆盖模型差异的通用宽容差。正式编辑器 S02 仍按原门槛复测，任何性能优化必须保留像素、历史及工程结果。
- **D-05 / D-11：** 打开工程时使用保存的文字栅格保留外观；明确进入编辑后才按 Windows 字体/布局重新排版。原字体可用时缩放重绘；缺字体时保留缓存并提示选择，禁止静默换字形。文字内容、字体身份及元数据不因栅格缓存丢失。
- **D-06：** 接受 S05 v2 对固定 R9 原型路径的资源可行性证据。早期 S02 超时仍是可复现的工程风险；W-019/W-030 集成同负载的全链路计时与逐阶段定位，正式 Alpha 不以原型通过代替性能门槛。
- **D-07：** 固定上述框架与既有锁文件，保留包内及上游声明身份。正式包必须按实际装载文件生成第三方清单，补齐 MicroCom 来源对应与适用声明；模型权重、HEIC 与运行时分别核对。当前私有原型包不可直接作为可发行包，也不在此作法律合规结论。

## 进入生产阶段时的保留条件

Qt 雅黑 ZIP 的正常退出及原文已复核，但没有原生预编辑事件，不能用它宣称 Qt 候选栏已修复。Avalonia 本轮没有定位到新 `--native-only` ZIP；此前真实微软拼音、DPI、焦点及 S05 的独立证据仍有效。第二输入法、双屏、物理鼠标及数位笔型号缺失的部分继续按设备矩阵安排，在实际设备可用时验收。HEIC 已有 Windows Server 原生解码筛查、BiRefNet 候选已有 Windows 11 单图与 Mac 读回；最终分发、模型质量和完整产品流程属于 M6/M7。

W-010–W-015 以一条可验证的工程读写编辑链路逐步交付；M3 Alpha、M4 文字、M5 高级工具、M6 Beta 与 M7 发布各按原计划独立验收。发布前必须解决所有产品与许可阻断项。
