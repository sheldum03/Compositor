# Windows 版详细开发计划

更新日期：**2026-10-02**。当前已确定 **Avalonia 为唯一生产路线，进入 M2 工程核心实现**。M0 设备矩阵及部分原型遗留项继续追踪；路线选择不代表所有环境验收完成。M2 尚未整体通过，M3–M7 与 Windows 1.0 尚未交付。

实施分支：`codex/windows-implementation`；本次核对的已提交基线为 `2ddf1f6`（含安全保存 `f705bd6` / `94ec810` 与图像 IO 切片）。9 月 29 日的[路线决定](m1-route-decision-20260929.md)放行 W-010 起的生产工作：Avalonia 11.3.22、.NET SDK 10.0.401 / net10.0、Skia 软件绘制、现有 C 算法 DLL。Qt 保留为技术对照，不进入生产构建。原规划分支为 `windows-part`。

产品范围保持：Windows 11 x64、v8 `.comp` 文件夹工程；原字体可用时缩放重绘，缺字体保留缓存画面与文字元数据并提示选择字体，禁止静默替换。完整目标仍按 [PRD](product-requirements.md)、[技术设计](technical-design.md)、[验证与发布](validation-release.md)及下文 W-001–040 验收。

### M2 已有实现与测试边界

当前源码位于 [Windows 生产工程](../../windows/README.md)，具体记录见 [M2 初始切片](evidence/production-core-m2-initial.md)、[保存故障测试](evidence/production-core-m2-save-faults.md)及[图像 IO 切片](evidence/production-imaging-m2.md)。它实现了一条受限的“读取→改名→撤销/重做→安全另存→重开→导出”链路，尚无生产编辑窗口。

- 本地 macOS arm64 Release 构建 0 警告、0 错误；瓦片快照、真实 C 像素桥接、v1–8 识别/写入保护及源 PNG 变化拒绝等冒烟通过。工程 reader 当前只核验 PNG 头部、尺寸及文件身份，尚未接入新增解码模块，不能算完整 reader 或合成。
- [Windows r2](evidence/production-core-windows-r2/README.md) 受限读写链路已实跑。第一次脚本在缺少 SDK 时误报 PASS，失败原始日志保留；已修正运行脚本检查。随后用固定便携 SDK 构建/运行成功，但取回的转储未捕获原生标准输出，完整输出目录尚未取回。
- [r3](evidence/production-core-windows-r3/README.md) 加入瓦片、原生桥接及两个资产安全反例，全新解压后的本地构建/冒烟通过；**Windows r3 尚未执行**。不能用 r2 为 r3 新代码背书。上一轮远程操作因 Mac 锁屏停止，该记录不代表当前仍锁屏，恢复测试前需重新观察现场。
- `64f903c` 修复打开后源 PNG 被外部改动仍可保存/导出的缺陷，并将源图尺寸与画布不同的受限工程标为只读；反例修复前失败、修复后本地通过。后续 `f705bd6` / `94ec810` 已修复损坏备份先移动、清理失败错误回滚、首次保存失败留下未校验正式目录三类缺陷；提交前三阶段故障及清理失败的本地检查通过。强杀/断电、底层写入、回滚本身失败、并发外部修改与 Windows 验证仍待完成。

- `2ddf1f6` 新增独立 PNG/JPEG 像素 IO：sRGB 预乘 RGBA、EXIF 1–8、透明 PNG、显式背景 JPEG、尺寸/截断输入及导出保护。10 组参考/PNG 往返通过、2 组 JPEG 背景最大差 1、8 条拒绝路径通过，独立 Pillow 复核通过；锁定恢复及 Release 构建 0 警告/错误。尚未接入导入/导出事务及生产窗口，Windows 未执行，不关闭 W-015。

### S02 / S05 最新有效结论

更新 P95 ≤16.7 ms、提交 P95 ≤100 ms、专用内存目标 ≤2 GiB 的 S02 门槛未降低。早期直接绘制版本的 11.2461/25.1137 ms 是历史结果，已不是当前性能进度。

| Windows 11 同机交替复测 | 空层更新 P95 | 已有层更新 P95 | 空层 / 已有层提交 P95 | 专用内存采样最大值 |
| --- | --- | --- | --- | --- |
| R9 首次 | 10.7406 ms | 11.2115 ms | 9.5076 / 11.8895 ms | 726,081,536 B |
| R8 对照 | 10.7937 ms | 12.4174 ms | 9.3096 / 11.7944 ms | 874,749,952 B |
| R9 再次 | 10.8541 ms | 10.9164 ms | 10.3401 / 9.7616 ms | 706,138,112 B |

三轮固定重放数值与图像复核通过，见 [R9→R8→R9 证据](evidence/lifecycle-s05/r9-s02-aba-followup.md)。此前 R9 两轮超时保留，间歇性等待原因尚未确认。计时止于 canvas lease 释放，不是物理输入至屏幕呈现；采样高水位不等于连续峰值。此前 GPU 对照性能/像素不通过，实验代码已撤回，未改变 CPU 生产路线。

[S05 v2 两轮前瞻复核](evidence/lifecycle-s05/resource-policy-v2/README.md)共 5,400 次编辑、108 张图像及两组七项资源检查通过；采样专用内存最大 592.26/544.53 MiB，最终旧文档弱引用为零。v2 修正判定参照区间，不能称为应用优化或泄漏修复。此结论只覆盖固定原型路径；正式应用须重做性能、资源和设备验收。

### 接下来按顺序推进

1. **补齐 M2 核心与保存保证（W-011–015）**：已补受控保存故障，继续完整资产/事务、像素合成与 v1–8 读取，并将实际 PNG/JPEG 解码导出接入可编辑文档和安全保存重开链路；补其余保存故障及平台验证。每个切片用反例和固定工程验证，受限只读是过渡保护，不是完整兼容目标。
2. **取得新版 Windows 核心证据（W-005/010–015）**：恢复现场后核对包与 SDK 身份，运行托管与原生 DLL 检查并取回日志及输出；r3 待验收期间继续不依赖远程设备的生产工作。
3. **接入唯一 Avalonia 生产入口（W-010、M3）**：依赖锁定、共享预览/导出、完整编辑历史和核心工作流逐步集成，正式应用重测原生输入、S02/S05；不把原型测试包称为 Alpha 安装包。
4. **按原范围完成 M4–M7**：文字/字体、高级工具、完整 IO/AI/Beta、安装签名更新；并行补齐设备、差分及[发行阻断](m1-dependencies-20260929.md)。全量验收通过才宣告 Windows 1.0 完成。

下文 M0–M7 与 W-001–040 保持完整。早期[后续任务清单](windows11-next-tasks.md)中“尚未选型”等历史状态以本节和路线决定为准，不据原型完成项计算产品完成百分比。

## 12. 角色、估算与风险

角色建议：产品负责人维护范围与体验；桌面负责人维护 UI/输入/安装；图像负责人维护合成/算法/性能；验证负责人维护样本和发布证据。一个人可以兼任多个角色，当前未指定人员。

M1 前不承诺日期。M1 后用四条代表路径的实测成本分别估算数据/文件、渲染/像素、交互/事务、文本/字体、发行/依赖五类剩余任务，记录预计人日、负责人、依赖、风险缓冲与里程碑日期；每周只用可运行产物和测试通过情况汇报进度，不用文件数或代码行数计算完成比例。

| 风险 | 触发信号 | 应对与验收 |
| --- | --- | --- |
| Mac 参考不可信 | 测试目标编译失败、旧通过数与当前提交不符 | W-001 先恢复基线；记录修复提交再生成参考图 |
| UI 选型不适合文本/笔刷 | IME、布局或交互门槛失败 | M1 暴露并复测，先决定框架再铺 UI |
| 跨平台结果不一致 | 蒙版边缘/混合/调整层差异 | 保存参考图和分项 diff，校准算子顺序及颜色/alpha |
| 文件格式漂移 | Mac 新增字段或版本 | 固定基线；每次同步有差异表和往返测试，不自动追随主线 |
| 字体重排破坏外观 | 打开即变化，或缩放时缺字体 fallback 覆盖缓存 | 打开使用保存栅格；缩放规则由 D-11 决定，明确编辑/栅格化可撤销 |
| GPU 数据交接过重 | kernel 快但交互仍慢 | 测整条通路，优先减少复制；允许 CPU 路线通过验收 |
| AI 权重或算子不可用 | 授权不明、CPU 内存过大、GPU fallback | 换经验证的权重/导出方式，保留可解释的 CPU 路径 |
| 发布依赖不齐 | 开发机正常、干净机启动/解码失败 | Beta 即打包验证，M7 才做最终签名发行 |

## 13. 每项任务的完成定义

任务只有在代码、对应需求行为、必要测试和构建都通过后才标完成。记录：W 编号、P 编号、提交、测试命令/环境、V 编号结果、性能数据（适用时）和剩余限制。文档任务以内容/链接/基线一致性检查为准，不为 Markdown 新建无意义测试框架。

每个 PR 控制在一个可审查目标；不顺手整理 Mac 代码或改无关格式。公共 C、格式和字体变更必须验证两端，未具备一端环境时明确列为未验证，不能假定通过。
