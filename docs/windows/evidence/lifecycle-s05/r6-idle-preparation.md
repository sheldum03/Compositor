# S05 R6：关闭后的自然空闲观测（2026-09-23）

**本地回放、图像独立复核及 Windows x64 构建通过；Windows 实机空闲结果尚未取得，资源稳定性仍未放行。** R5 最终自然样本只等待文档关闭后 1 秒，随后即执行诊断 GC。它不足以回答正常空闲时托管对象、堆容量和进程占用是否继续回落。

新增独立 `--s05-idle-window` 和本地 `--s05-idle-check`：保持九轮 900 次编辑及历史/保存/重开原工作量，在最后一次自然关闭采样后增加 60 秒空闲，再做原有最终诊断 GC。空闲初始及每十秒记录一次，共七次，包含私有内存、工作集、托管内存、GC 快照和旧文档弱引用数量。期间不编辑、不主动回收、不序列化报告；采样本身仍有少量分配。原三轮及九轮入口不增加等待，不改变 S02 算法或任何性能门槛。

新增 `review-s05.py <report> --idle` 要求完整九轮、版本 3、与最后自然关闭样本相同的起点、七次有序采样覆盖至少 60 秒、累计计数不倒退及其后的最终诊断 GC。本地必须另加 `--allow-local`。内存回落或持平都只是观察，不能据此自动接受 native 资源、长期平台或完整 S05。

已完成验证：

- 固定 SDK 10.0.401 SHA-512 验证通过；依赖按原 lock 恢复，Release 编译零警告/错误。Windows RID 使用单独的临时锁文件，原 24 项包定义、版本和内容 hash 逐项相同，仓库 lock 未修改。
- [本地新增模式](r6-local-idle-review.json)：900 编辑、900 撤销、900 重做、18,900 回调；七次自然采样从 0 到 60,017.4091 ms，最终旧文档引用为零。九组 4000×4000 final/reopened PNG 独立 RGBA 精确。
- [原三轮入口](r6-local-default-review.json)：300 次编辑及对应历史、保存重开通过，空闲采样为空；三组 PNG 也与新模式精确相同。共同 RGBA SHA-256 为 `a8a62c6c48e71e2ce419ee56802d7160c0beaeded89c386d903ac60deba58a8e`，与 R5 Windows 最终图一致。
- [真实报告负例](r6-negative-checks.json)：不足 60 秒、缺样本、GC 计数倒退、本地结果冒充 Windows 均被拒绝。既有 Windows R5 按原 `--soak --gc-diagnostics` 仍通过，作为 `--idle` 证据被拒绝。
- Windows x64 framework-dependent 发布通过；尚不把构建成功记为实机运行。

[原始证据及源码身份](r6-preparation-identity.json)记录完整本地 ZIP 和生成 DLL 的 hash。下一步将独立安装目录中的 R6 在 Windows 执行，取回原始采样、退出码和九组图像，再判断空闲是否消除此前的占用现象。即使自然空闲内存下降，也仍需区分 GC 容量保留与 native 分配，不能放宽资源标准或跳过 M1。
