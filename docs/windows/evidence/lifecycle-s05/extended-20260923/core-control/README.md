# 笔刷核心对照

这是一次性诊断，不接入应用或 CI。保留相同的 27 × 100 次笔刷/撤销/重做与自然关闭等待，去掉原生窗口、Skia 绘制、PNG 保存读回和逐帧诊断记录。它能检查“只有笔刷与历史时是否也出现 GC 容量波动”，不能单独区分被同时移除的各环节，也不能代替原生 S05。

实际构建目录包含本页的 `Program.cs` / `CoreControl.csproj`，以及从基础提交复制的 `SoftBrushStroke.cs`、`TiledRaster.cs`、`TileImageCache.cs`。三份代码未修改，SHA-256 在 [manifest.json](manifest.json)；复现时将对应版本文件复制到独立临时目录再构建，不直接在此证据目录执行缺少源文件的项目。完整副本及 DLL 在外部证据 `S05Core.zip` 中。

本地执行 200.60 秒、2,700 次编辑和全部历史摘要检查通过。GC committed 在轮次间波动，最终诊断 GC 后文档引用为零、托管内存 137,408 B。macOS 专用内存 API 返回 0，不当作实测 0 内存；本地结果不计入 Windows 验收。

Windows 启动器先检查此前 PID 40896 的原生长测已经保存退出码与复核码，防止两个负载并行干扰。独立目录运行，不修改 GC 环境配置或原测试文件。Windows PID 49836 已执行完成，退出 0，stderr 为空。用时 213.12 秒，27 轮全部历史摘要检查通过。见 [原始报告](windows-report.json)、[进程身份](windows-identity.json)和 [ZIP 身份](windows-archive.json)。原始包 SHA-256 / 大小 / CRC 与终端输出匹配；记录的 DLL hash 与准备包一致。

实机自然关闭后专用内存在 164.81–268.52 MiB 之间重复波动，第 10、17、24 轮均回落；空闲末尾约 252.41 MiB。最终诊断 GC 后旧文档引用为零、托管对象 304,448 B、GC committed 210,796,544 B、专用内存 230,563,840 B。核心路径本身即可出现空间保留，不需要原生绘制或完整报告才能出现；两进程节奏不同，不能据此分摊 UI 和报告的精确占用。
