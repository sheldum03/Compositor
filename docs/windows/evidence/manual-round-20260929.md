## 本轮取回并独立复核的原始文件

- [Qt 字体对照 ZIP](qt-native-ime-windows/candidate-diagnostic/control-comparison/font-20260929-raw.zip)：Windows 测试根目录 `qt-ime-font-20260929-093610.zip`，5272 字节，SHA-256 `15100ab60ac7dd4d2edd57e3ea9a583e23e67f72670e82738aa8b1dece9e9910`。UU 显示“已接收”；本地摘要与 Windows 启动器输出一致；ZIP CRC 及 `files.json` 中 7 个成员摘要通过。
- `identity.json` 记录 Windows 11 Build 26200，Qt 6.11.2；思源黑体 PID 17968 与 Microsoft YaHei UI PID 28284 均退出码 0，两个进程记录的请求字体与 Qt 匹配字体一致。两个 `closed` 事件中的固定原文逐字完整，无提交文字。
- 思源黑体日志 52 条，其中 10 条 `input-before`、10 条 `input-after`。预编辑从 `z` 增至 `zhong'wen`，第二段布局由 1 行增至 2 行，Qt 光标纵坐标从 84 变为 135。会话中已直接观察到候选栏留在旧行，Esc 后原文保留。日志记录的 IMM 候选设置点随布局变化；该查询值不能替代候选栏真实屏幕位置。
- Microsoft YaHei UI 日志只有 7 条：打开、5 条光标变化、关闭，**没有任何输入事件或非空预编辑**。原文和正常退出已复核，但原始记录不能证明发生了自动换行，也不能证明候选栏跟随。用户“全部正常”仅作为人工反馈，雅黑与思源的候选位置差异仍未成立。此前两个 Qt 控件及思源字体的候选栏偏移证据仍保留。
