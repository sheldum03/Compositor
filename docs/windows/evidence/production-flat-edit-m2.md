# M2 平面多层元数据事务与保存（2026-10-02）

将 v8 中所有图层均为全画布、未变换、Normal、透明度 1、无蒙版/组/额外语义且总源像素不超过 100 MP 的工程纳入可编辑子集。`ProjectSession` 对按底到顶的图层顺序提供基于 GUID 的改名、显隐与移动操作；每次实际变化形成一个快照，无变化不增加历史。像素替换仍只允许单层，复杂工程继续只读。

安全保存现在复制并验证每个图层资产的 SHA-256，然后验证新工程，再按既有同目录临时目录/备份流程提交。保存点、撤销/重做、各图层 ID 和原始 PNG 字节保持。`ImageProjectWorkflow` 的同一合成器既能读取当前未保存元数据状态，也用于导出；原 `ProjectStore.ExportPng` 拒绝把某一层原始 PNG 误称为多层工程导出。

`Compositor.Workflow.Checks` 用两层 300×300 真实 v8 工程验证：可见图层移动确实改变合成顺序；改名、隐藏、移动分别撤销/重做；保存后所有源资产字节相同、重开图层 ID/顺序/可见性及导出像素一致；外部改变任一资产后保存被拒绝且不留下正式目录或临时文件；非 Normal、非 1 透明度、非默认变换和蒙版工程仍不可编辑。单层 v1 仍可打开并导出，避免多层导出接入使原格式回归。macOS arm64 .NET 10.0.401 Release 工作流检查退出 0。修改保存代码后，原八个单层真实子进程强杀场景重新运行全部通过；这不等于多层强杀覆盖。

逐层像素编辑、图层增删/复制、组/蒙版编辑、独立蒙版位置及更复杂混合尚未实现。真实 Mac 对修改后工程的打开/渲染/继续编辑、Windows 实机执行与多层保存中断仍待验收；r4 固定包不含此改动。M2/M3 不据此关闭。
